# Benchmarks — honest numbers only

Run the harness and store the JSON reports here:

```bash
python scripts/benchmark.py --input demo/sample_inputs/fake_dashboard.png \
  --repeat 20 --output benchmarks/<name>_run.json
```

Naming convention: `<machine>_<backend>_run.json` — e.g.
`linux_cpu_dev_run.json`, `mac_cpu_dev_run.json`,
`snapdragon_qnn_run.json`.

## What each report contains

- OCR / detection / total latency: mean, median, p95, min, max
- RSS memory start + peak
- OCR engine, semantic engine, ONNX Runtime providers, acceleration status
- Privacy measurement for the run (new outbound connections — expected 0)

## Interpreting the recorded runs

- `linux_cpu_dev_run.json` — recorded on the development container with the
  **simulated-sidecar** OCR engine. It measures the detector + pipeline
  overhead, **not** real OCR latency. Real EasyOCR numbers will be far
  higher and must be recorded on the target machine.
- Any file marked `"status": "not yet run"` is a placeholder keeping the
  evidence structure honest. **Do not fabricate numbers.** Replace a
  placeholder only with output from an actual run.

## Rules

1. Never edit numbers by hand — reports are generated by `scripts/benchmark.py`.
2. NPU claims require `QNNExecutionProvider` on the machine that produced
   the report (`meta.onnxruntime.available_providers` must show it).
3. Include the command used to produce each report in the file name or PR
   description.
